# aka-ossbss 画面仕様

- 対象: aka-ossbss の画面（URL、使える役割、項目、操作、誤りの文）。文言はテンプレート（`internal/web/templates`）とコードの文を写した。
- 関連: [README](../README.md)、[設計概要](design-overview.md)（§5 の権限の表、§19.2 の段階の記録）、[運用ガイド](operation-guide.md)
- RadSec の受け口の画面（エッジ、テナントの配置、AP・グループ、持ち込みの CA）は段階 4 で足す。

役割の呼び名は、A テナントユーザー、B テナント管理者、C 運用担当、D システム管理者。

## 1. 共通

### 1.1 画面の作り

- 見た目は daisyUI。テーマはブラウザの設定（ライト / ダーク）に従う。JavaScript は書かず、画面の一部の差し替えは htmx で行う。CSP でスクリプトとスタイルは同梱のファイルだけに限る。
- ヘッダーに「aka-ossbss」（トップへのリンク）、メールアドレス、役割、所属のテナント、「ログアウト」（Cloudflare Access のログアウト `/cdn-cgi/access/logout`）を出す。開発用の設定で動くときは「開発用の設定」のバッジを出し、ログアウトは出さない。フッターに版（`OSSBSS_VERSION`）を出す。
- ナビゲーションは役割で出し分け、開いている画面の項目を強調する。

| 項目 | URL | A | B | C | D |
|---|---|---|---|---|---|
| ダッシュボード | `/` | ○ | ○ | ○ | ○ |
| 加入者 | `/subscribers` | ○ | ○ | ○ | ○ |
| セッション | `/sessions` | ○ | ○ | ○ | ○ |
| 一括投入 | `/jobs` | | | ○ | ○ |
| 突き合わせ | `/reconcile` | | | ○ | ○ |
| 課金レコード | `/charging` | | | ○ | ○ |
| テナント | `/tenants` | | | ○ | ○ |
| アカウント | `/accounts` | | ○ | | ○ |
| 監査ログ | `/audit` | | ○ | ○ | ○ |

- 画面の上部に、成功の文（緑）とエラーの文（赤）を出す。入力の誤りは各項目の下にも出す。htmx の要求でも 4xx・5xx の本文を差し替えて出す。htmx の要求でエラーの画面を返すときは、本文全体を置き換える。
- エラーの画面は状態の符号と文を出す。利用者が分かるときは、案内のリンク（「アカウントの一覧へ」など。あるときだけ）と「トップへ」のボタンを出す。
- ページが見つからないとき: 404「ページが見つかりません。」。
- 別の出どころからの POST は 403「この操作は受け付けられません。画面を開き直してから操作してください。」。
- 日時はサーバーのタイムゾーン（`TZ`。既定は日本時間）で `2006-01-02 15:04:05` の形に出す。値がないときは `-`。

### 1.2 権限とテナントの範囲

- 権限は[設計概要](design-overview.md) §5 の表のとおり（`internal/authz`）。画面に出さないだけでなく、要求を受けたときにも必ず判定する。
- A・B が扱えるのは自分のテナントのものだけ。範囲の外の IMSI を開いたり送ったりしたときは、存在しないときと同じ 404「加入者 … は見つかりません（このテナントに属していないか、登録されていません）。」を返す。存在の有無を漏らさないため。
- 範囲の中でも、役割にない操作は 403「この操作の権限がありません。」。範囲を絞らない画面（一括投入、突き合わせ、課金レコード、テナント、aka-provisioner と下流の監査ログ）は、A・B には 403。
- A・B の `tenant` の指定（`?tenant=`）は無視し、自分のテナントに固定する。
- A・B の画面には AMF・SQN・SQN の方式・許可クライアントを出さない。一覧では vecgen 側を読まないので、vecgen 側の「下流にない」も出さない。
- 利用者の識別:

| 場合 | 状態の符号と文 |
|---|---|
| Cloudflare Access の JWT がない・検証できない | 401「Cloudflare Access を通して開いてください。」 |
| Access の公開鍵を取得できない | 503「利用者を確かめられません（Cloudflare Access の公開鍵を取得できません）。しばらくしてから開き直してください。」 |
| アカウントがない、または無効 | 403「この利用者（…）は登録されていません。管理者に登録を依頼してください。」と「別のメールアドレスでログインし直す」 |
| DB を使えない | 503「データベースに接続できません。しばらくしてから開き直してください。」 |

### 1.3 状態の呼び方

| 値 | 画面 | 色 |
|---|---|---|
| `active` | 利用中 | 緑の枠 |
| `inactive` | 停止中 | 黄 |
| `terminated` | 解約 | 赤 |
| その側がない | なし | 灰の文字 |

側の名前は「vecgen 側（aka-vecgen）」「radius 側（aka-radius）」。

### 1.4 確認ダイアログ

- 取り返しのつきにくい操作の前に、確認ダイアログ（daisyUI の `modal`、`<dialog>`）を出す。HTML の Invoker Commands（`<button command="show-modal" commandfor="…">`）で開き、「やめる」とダイアログの外を押すと閉じる。確認のボタンは、送るフォームを `form` 属性で指す。

| 操作 | 文 |
|---|---|
| 解約する | `<側>`を解約（Terminated）にします。解約から戻せるのはシステム管理者だけです。よろしいですか？ |
| 物理削除 | `<側>`からこの加入者を物理削除します。元に戻せません。よろしいですか？ |
| 所属のテナントの付け替え | 所属のテナントを付け替えます。radius 側のルールのテナントも書き換えます。よろしいですか？ |
| ジョブの中断 | 処理中の行を終えてから止めます。処理した行は元に戻さず、再開もしません。同じファイルを投入し直せば、残りだけが処理されます。 |
| 突き合わせの「下流から削除する」 | 選んだ側の加入者を下流から物理削除します。利用中（Active）のものは止めてから消します。元に戻せません。 |
| テナントの削除 | テナント「…」を削除します。監査ログは残ります。よろしいですか？ |
| アカウントの無効化 | アカウント … を無効にします。次の要求から、この利用者は画面を使えなくなります。よろしいですか？ |
| アカウントの削除 | アカウント … を削除します。監査ログは残ります。よろしいですか？ |
| 止める（側ごと） | `<側>`を止めます。次の認証から拒否します（接続中のセッションは切れません）。よろしいですか？ |
| 両方を止める | vecgen 側と radius 側を止めます。次の認証から拒否します（接続中のセッションは切れません）。よろしいですか？ |
| ジョブの「投入する」 | 待ち行列に入れます。処理した行は元に戻しません（中断はできますが、再開はしません）。よろしいですか？ |
| 課金レコードの「今すぐ締める」 | 締めていない過去の月を締め、通し番号を割り当てます。締めた月は取り消せません。よろしいですか？ |
| 課金レコードの「作り直す」 | `<月>` のファイルを今の鍵で作り直し、版を上げます。古い版も残ります。外部のシステムには新しい版を渡してください。よろしいですか？ |

状態の「使う」「両方を使う」（認証を止める誤操作にならない）、ファイルのない月の「作る」、削除済みの IMSI の「承認して含める」「除いて進める」（理由と選択を画面で確かめる）は、確認ダイアログを出さない。

### 1.5 二重送信の防止（Idempotency-Key）

- aka-provisioner への書き込みのフォームには、描くたびに作るキーを隠し項目 `idem` で持たせ、`Idempotency-Key` として送る。同じフォームを送り直しても、aka-provisioner は最初の結果を返す（段階 3-1 の W12）。
- 加入者の詳細は、画面ごとのキーにフォームの名前を付ける（`<キー>-state-<側>-<状態>`、`-both-<状態>`、`-delete-<側>`、`-reinstate-<側>`、`-vecgen`、`-source`、`-move`）。両側に続けて書くときは、さらに側の名前を付ける（`-both-inactive-radius`）。
- 登録のフォームと認可ポリシーの編集は、aka-provisioner に届かなかった・結果が分からないときは同じキーを残し、aka-provisioner が 4xx を返したときは新しいキーにする（入力を直して送ると内容が変わるため）。
- 加入者の詳細の操作も同じ。結果が分からないときは同じキーのまま描き、aka-provisioner が 4xx を返したときと、aka-ossbss が呼ばずに断ったときは新しいキーにする（両側に続けて書いて片方でも結果が分からなければ、同じキーのまま）。
- 一括投入の行のキーは `job-<ID>-<IMSI>`、突き合わせの対応のキーは `reconcile-<ずれの番号>-…`。

### 1.6 aka-provisioner の誤り

| 場合 | C・D | A・B |
|---|---|---|
| aka-provisioner に接続できない | 原因の見当（証明書の未登録、サーバー証明書の不一致、共有ネットワークなど。`internal/provisioner/diagnose.go`） | aka-provisioner に接続できません。しばらくしてからもう一度操作してください。続く場合は運用担当に連絡してください。 |
| 下流に接続できない（503 `DOWNSTREAM_UNAVAILABLE`） | aka-provisioner から `<下流>` に接続できません。ダッシュボードで接続の状態を確かめてください。 | aka-provisioner から `<下流>` に接続できません。しばらくしてからもう一度操作してください。続く場合は運用担当に連絡してください。 |
| 下流の内部の誤り（5xx） | `<下流>` が誤りを返しました（状態の符号 `cause`）。 | `<下流>` で誤りが起きました。しばらくしてからもう一度操作してください。続く場合は運用担当に連絡してください。 |

どの役割にも同じ文を出すもの:

| `cause` | 文 |
|---|---|
| `USER_NOT_FOUND` | `<下流>`にこの加入者がありません（aka-ossbss の外で削除された可能性があります。台帳は突き合わせで直します）。 |
| 既にある | `<下流>`には、この IMSI の加入者が既に登録されています（台帳にない場合は、aka-ossbss の外で登録されたものです。システム管理者に連絡してください）。 |
| `SUBSCRIBER_ACTIVE` | 利用中（Active）の加入者は物理削除できません。先に止めるか解約してください。 |
| `SUBSCRIBER_TERMINATED` | 解約（Terminated）の加入者は変更できません。システム管理者が戻してから変更してください。 |
| 状態を移せない | その状態には変えられません（解約からは、システム管理者が「戻す」で停止中に戻します）。画面を開き直してください。 |
| AV クライアントがない | 選んだ許可クライアントが aka-vecgen にありません。画面を開き直してください。 |
| 取得先がない | 選んだ取得先が aka-radius の登録簿にありません。画面を開き直してください。 |
| `OPERATION_IN_PROGRESS` | 同じ操作が処理中です。少し待ってから、画面を開き直して確かめてください。 |
| `IDEMPOTENCY_KEY_MISMATCH` | 送信の内容が前回と違います。画面を開き直してから、もう一度操作してください。 |
| `DOWNSTREAM_ERROR` | `<下流>` が不正な応答を返しました（状態の符号）。 |
| `ROUTE_NOT_ALLOWED` | aka-provisioner がこの口を通しませんでした（aka-provisioner の版を確かめてください）。 |
| 400 と `invalidParams` | 入力が正しくありません（項目の名前）。 |

**結果が分からないとき（段階 3-1 の W7）**: aka-provisioner に届かない・応答がない・5xx のときは、台帳を変えずに印（`check_needed`）を立て、その場で両側を読み直す。

- 読み直せたら: 「`<側>`の`<操作>`の結果が分かりませんでした（aka-provisioner か下流が応答しませんでした）。読み直して台帳を下流に合わせました。今の状態を確かめてください。」
- 読み直せなければ: 「`<側>`の`<操作>`の結果が分かりませんでした（aka-provisioner か下流が応答しませんでした）。結果を確かめています。しばらくしてから開き直してください。」
- 印の立った加入者の詳細には「結果を確かめています（下流の結果が分からなかった操作があります。aka-provisioner と下流が応答するようになったら、開き直すと台帳を下流に合わせます）。」を出す。開いて読み直せたら「結果が分からなかった操作を読み直し、台帳を下流に合わせました。」。5 分ごとの処理（§7.3）でも読み直す。
- 下流は成功したのに台帳を書けなかったとき: 「`<側>`の`<操作>`は済みましたが、台帳を書けませんでした（結果を確かめる印を付けました）。」
- 認可ポリシーの保存は台帳に関わらないので印を立てない（§3）。

### 1.7 監査ログ

成功した変更の操作と、結果が分からなかった操作（内容の `result` が `unknown`）を、PostgreSQL の `audit_log` と日ごとのファイルに残す。項目は、操作者のメールアドレスと役割、対象のテナント（ないものは「なし」）、操作、対象、内容（変えた項目の名前など）、トレースID、接続元、ジョブの ID。Ki・OPc は入れない。定刻の処理の操作者は `system`。閲覧の画面は §11。

| 操作（`action`） | 画面の名前 |
|---|---|
| `subscriber.vecgen.create` / `subscriber.radius.create` | vecgen 側の登録 / radius 側の登録 |
| `subscriber.reregister` | 削除済みの IMSI の登録し直しの承認 |
| `subscriber.vecgen.update` | vecgen 側の変更 |
| `subscriber.radius.source` | 取得先の変更 |
| `subscriber.radius.rules` | 認可ポリシーの変更 |
| `subscriber.state` / `subscriber.reinstate` | 状態の変更 / 解約からの戻し |
| `subscriber.delete` | 物理削除 |
| `subscriber.tenant` | 所属のテナントの付け替え（移動元と移動先のテナントに 1 行ずつ） |
| `subscriber.check` | 結果の確かめ（台帳の補い） |
| `subscriber.external` | 回線の外部の番号の変更 |
| `tenant.create` / `tenant.update` / `tenant.delete` | テナントの作成 / 名前の変更 / 削除 |

## 2. 加入者

一覧・件数・絞り込みは台帳で行い、下流の値はそのページの分だけを読む（設計概要 §7.3）。

### 2.1 一覧（`/subscribers`）

全員が使える（A・B は自分のテナント）。見出しに条件に合う件数を出し、50 件ずつ IMSI の順に出す（「次のページ」「先頭へ」）。

| 絞り込み | 値 | 誤り（400） |
|---|---|---|
| `prefix` IMSI の前方一致 | 15 桁までの数字 | IMSI の前方一致は 15 桁までの数字で指定してください。 |
| `tenant` テナント（C・D） | すべて、各テナント | テナントの指定が正しくありません。 |
| `vecgen`・`radius` 側ごとの状態 | すべて、利用中、停止中、解約、なし | 状態の指定が正しくありません。 |
| `source` 取得先 | すべて、台帳にある取得先 | 取得先の指定が正しくありません。 |
| `mismatch` 食い違いだけ、`check` 確かめているものだけ、`deleted` 削除済みだけ | チェック | |
| `cursor` ページの位置 | IMSI | ページの位置の指定が正しくありません。 |

| 項目 | A・B | C・D |
|---|---|---|
| IMSI（詳細へのリンク） | ○ | ○ |
| テナント | | ○ |
| vecgen 側の状態（「下流にない」のバッジ） | ○ | ○ |
| AMF・SQN | | ○ |
| radius 側の状態（「下流にない」のバッジ） | ○ | ○ |
| 取得先 | ○ | ○ |
| ルール（件数） | ○ | ○ |
| バッジ（削除済み、確かめています、食い違い） | ○ | ○ |

- 削除済みは「削除済みだけ」を選んだときだけ出す。
- 下流を読めないときは「`<下流>` を読めませんでした。台帳の値だけを出しています（「-」の列）。」と出し、台帳の列は出す。
- 操作: 「vecgen 側の登録」（D）、「radius 側の登録」（C・D）。

### 2.2 登録（`/subscribers/new?side=vecgen|radius&imsi=…`）

vecgen 側は D、radius 側は C・D（段階 3-1 の W4）。側を指定しないとき、D は vecgen 側、C は radius 側を開く。D には 2 つの側を切り替えるタブを出す。C が vecgen 側を開くと 403。

| 項目 | 内容 | 誤りの文 |
|---|---|---|
| IMSI | 15 桁の数字 | IMSI は 15 桁の数字で入力してください。 |
| 所属のテナント | 台帳にない・削除済みの IMSI で選ぶ（既定は「選んでください」）。もう一方の側が登録済みなら台帳の値で固定し、「もう一方の側の登録で決まっています（付け替えはシステム管理者が詳細で行います）」と出す | 所属のテナントを選んでください。／選んだテナントはありません。画面を開き直してください。 |
| 登録のときの状態 | 利用中（既定）、停止中 | 登録のときの状態を選んでください。 |

vecgen 側の項目:

| 項目 | 内容 | 誤りの文 |
|---|---|---|
| Ki・OPc | 16 進 32 桁。aka-vecgen に送るだけで、aka-ossbss には残さず、誤りのときも画面に戻さない。登録の後は変えられず、画面にも出さない | Ki は 16 進 32 桁で入力してください。 |
| AMF | 16 進 4 桁（既定 `8000`） | AMF は 16 進 4 桁で入力してください。 |
| SQN | 16 進 12 桁（既定 `000000000000`） | SQN は 16 進 12 桁で入力してください。 |
| SQN の方式 | `inc1`、`inc32`（既定）、`inc33` | SQN の方式を選んでください。 |
| 許可クライアント | aka-vecgen の AV クライアントから選ぶ（空でもよい）。ないときは「AVクライアントがありません（aka-vecgen のコマンドで登録します）。」 | 許可クライアントの指定が正しくありません。 |

radius 側の項目:

| 項目 | 内容 | 誤りの文 |
|---|---|---|
| 取得先 | aka-radius の取得先の登録簿から選ぶ | 取得先を選んでください。 |
| 最初のルール | NAS-Identifier（既定 `*`）・SSID（既定 `*`）・VLAN・Session-Timeout（§3）。ルールのテナントは所属のテナント | ルールの入力を確かめてください。 |

### 7.3 保留と対応

**保留**: 自動で直す数が上限（`OSSBSS_RECONCILE_MAX_FIXES`）を超えたら何も直さない。「直す数（… 件）が上限を超えたので、何も直していません。」「下流を古いバックアップから戻したときや接続先の設定を誤ったときに、台帳と課金レコードを大量に書き換えないための保留です。内容を確かめてください。」を出す。ダッシュボードにも警告を出す。

- D の「このまま直す」（`POST /reconcile/{id}/approve`）: 「承認の理由（必須）」。下流を読み直してから、新しい実行として直す。
- 誤り: 「承認の理由を 500 文字までで入力してください。」「この実行は保留の最新の実行ではありません。」「突き合わせが動いています。終わってからもう一度押してください。」。

**対応**（`POST /reconcile/{id}/findings`）: D だけ。対応できるのは、完了か保留の最新の実行のずれだけ（古い実行には「新しい実行があるので、この実行のずれには対応できません。最新の実行で対応してください。」）。選べるのは対応待ちの `downstream_only`・`deleted_present` で、1 回 100 件まで。実行のときに下流を読み直し、解消していれば何もしない。

- 「取り込む」: 「取り込むテナント」を選ぶか、行のテナントの候補を使う（ルールのテナントが全部同じならそれ、削除済みなら前のテナント）。ルールのテナントが選んだテナントと違えば、ルールを書き換えてから取り込む。IMSI ごとに両側をまとめて取り込む。
- 「下流から削除する」（確認あり）: 選んだ側を物理削除する。利用中のものは止めてから消す。
- 結果: 「取り込み … 件、解消済み … 件。」「下流からの削除 … 件、解消済み … 件。」。失敗は「… 件は失敗しました（対応待ちのままです）。」と IMSI ごとの文（20 件まで。「テナントがありません。」「下流を読めませんでした。」、ほかは §1.6）。
- 誤り: 「対応するずれを選んでください。」「1 回に対応できるのは 100 件までです。」「理由は 500 文字までです。」「選んだテナントはありません。」「対応できるのは最新の実行のずれだけです。」「削除済みの IMSI を取り込むには、理由を入力してください。」「テナントの候補のない IMSI（…）があります。取り込むテナントを選んでください。」「ずれの指定が正しくありません。」。

**印の読み直し**: `check-needed` が 5 分ごとに `check_needed` の行を 100 件まで読み直す（§1.6）。
